# SalesNow Webスクレイピング課題

上場企業10社の公式サイトのトップページからリンクをたどってクロールし、
**本社住所・代表者氏名・資本金・設立年月** を抽出して JSON / CSV に出力するプログラムです。

> **生成AIの利用について（重要）**
> 課題Aでは「生成AIを使ってデータを抽出する」ことが求められていますが、本提出物の**抽出処理は生成AIを使用しないルールベース（Python のみ）**です。
> 開発途中で Claude API による構造化抽出を実装し、実際に API を呼び出しましたが、APIキーのクレジット残高不足でエラーになりました（`report.md` 参照）。そのため、生成AIを使わない方針に切り替えました。
> 生成AI（Claude Code）は**開発支援**に使用しており、そのプロンプトと回答の履歴を `prompts/` に保存しています。

## ディレクトリ構成

```
├── prompts/                 # 開発に使用した生成AI（Claude Code）とのプロンプト・回答履歴（txt）
├── result/
│   ├── companies.json       # 抽出結果（根拠URL・根拠テキスト・検証結果つき）
│   └── companies.csv        # 同内容のフラット版（UTF-8 BOM、Excelで文字化けしない）
├── src/
│   ├── companies.csv        # 入力：企業名とURL（10社）
│   ├── main.py              # エントリポイント（クロール→抽出→検証→出力）
│   ├── crawler.py           # 同一ドメイン内のベストファースト・クローラ
│   ├── content.py           # HTML→テキスト、表/dl のラベル・値ペア抽出、沿革の解析
│   ├── extractor.py         # 項目ごとの抽出・クリーニング・検証
│   └── taskb_probe.py       # 課題B：Indeed のBot対策の観測用スクリプト
├── tests/test_extraction.py # オフライン単体テスト（ネットワーク不要）
├── requirements.txt
├── README.md
└── report.md                # 技術選定の比較、課題Bの考察
```

## 環境構築

Python 3.10 以上が必要です（Python 3.12 で動作を確認しました）。

```powershell
git clone https://github.com/<owner>/salesnow-web-scraping.git
cd salesnow-web-scraping
py -3.12 -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

APIキーや `.env` は不要です。

## 実行方法

```powershell
# 10社すべてを処理して result/ に出力（約1分）
python src/main.py

# 1社だけ処理する
python src/main.py --only タマホーム

# オプション
#   --input      入力CSV（既定: src/companies.csv。列: company_name,url）
#   --out        出力ディレクトリ（既定: result）
#   --max-pages  1社あたりの最大取得ページ数（既定: 12）
#   --delay      リクエスト間隔（秒、既定: 1.0）
```

Windows のコンソールで日本語ログが文字化けする場合は、`python -X utf8 src/main.py` で実行してください。

入力CSVに行を追加すれば、他の企業にもそのまま適用できます。

## 処理の流れ

1. **クロール（`crawler.py`）**
   - トップページから開始し、リンクのアンカーテキストとURLをスコアリングします（会社概要・企業概要・company/profile・outline・gaiyou 等は加点、IR・ニュース・採用・商品等は減点）。スコアの高いリンクから順に辿ります（優先度付きキュー）。
   - 同一サイトのドメインとそのサブドメインのみを対象にします（例：`www.sakataseed.co.jp` → `corporate.sakataseed.co.jp` は許可、外部の親会社サイトは除外）。
   - `robots.txt` を遵守し、リクエスト間隔は既定で1秒、タイムアウトは20秒です。5xx・接続エラーは1回リトライします。URLは重複排除し、リダイレクト先も重複チェックします。
   - 4項目のラベル（本社/所在地・代表者・資本金・設立）が表に揃った時点で停止します。ただし設立が「昭和18年(1943年)」のように**月を含まない場合は、沿革（沿革・歴史・history・rekishi）ページに限定して追加でクロール**し、設立月が見つかった時点で停止します。
2. **抽出（`content.py` / `extractor.py`）**
   - `<table>` の th/td、`<dl>` の dt/dd、「ラベル行の次の行が値」というレイアウトから、ラベルと値のペアを取得します。
   - 項目ごとにラベルの優先順位を定義しています（例：「本社所在地」＞「本社」＞「所在地」）。
   - クリーニング処理：
     - 住所：郵便番号を `postal_code` に分離し、TEL・地図・アクセス案内を除去します。
     - 代表者：役職を除去します。代表取締役が複数いる場合は社長を優先します。
     - 資本金：「(2026年3月31日現在)」等の注記を除去します。
     - 設立：`YYYY年M月` に正規化します（和暦は西暦に換算）。
   - 設立月がプロフィールに無い場合は、沿革のタイムライン（「昭和39年」→「7月」→「…を設立」）を上から読み、該当年の最初の「設立」行から月を取得します。
3. **検証**：各項目について次の3点を確認し、`verified` に記録します。
   - 根拠テキスト（evidence）が出典ページ上に実在するか
   - 値が根拠テキストから導出できるか
   - 値が期待する形式に合っているか（都道府県から始まる住所、`円`で終わる金額、`YYYY年M月` 等）
4. **出力**：`result/companies.json` と `result/companies.csv` に出力します。

## 出力スキーマ

`companies.json` の1要素：

| キー | 内容 |
|---|---|
| `company_name`, `url` | 入力値 |
| `status` | `ok`（4項目取得）/ `partial` / `not_found` / `error`（ページ取得不可） |
| `postal_code` | 本社の郵便番号（ページに記載がある場合） |
| `head_office_address` / `representative` / `capital` / `established` | `{value, source_url, evidence, verified}` |
| `crawled_pages` | 実際に取得したURL（取得順） |
| `missing_fields` / `unverified_fields` | 取得できなかった項目 / 検証に通らなかった項目 |
| `errors` | HTTPエラー・robots.txt による除外など |
| `extracted_at` | 取得日時（UTC） |

CSVは同じ情報を1社1行に展開したものです（`<項目>`, `<項目>_source_url`, `<項目>_verified`）。
